## Оперативное запоминающее устройство
**ОЗУ** предназначено для хранения программы, выполняющейся в компьютере.
**Тег** - поле служебной информации
**Машинное слово** - поле программно изменяемой информации
![[Pasted image 20250918085401.png]]

Вектор ячеек памяти, где у каждой ячейки есть адрес. Адерсация сплошная и со сдвигом.

Может 2 поля: поле машинного слова и поле (которое может быть) тега (признака). В поле признака программа аппаратным образом размещается специальная информация, которая может использоваться для разных целей.

### Как могут использоваться теги
1. Для контроля за целостностью данных, находящихся в машинном слове.
![[Pasted image 20250911113426.png]]
При записи в машинного слова кода, автоматически контроль памяти подсчитывает количество двоичных единичек и дополняет в бит чётности разряд до чётного количества единичек
Если мы считываем информацию, то происходит подсчёт единичек и сверка с контрольным разрядом. Если кол-во единичек чётное колчество, а в теге единичка, то ловим прерывание. Если в коде нечёт кол-во единичек, а в теге единичка, то всё хорошо.

2. Контроль доступа к командам/данными
	- Если 0, то в машинном слове данные, если 1 - команда.
3. Контроль доступа к машинным типам данных
	- Есть системы, в которых сузествует высокоуровневый контроль за данными, тогда в теге находится код типа машинных данных.
	- **Машинный тип данных** (в информатике и компьютерном программировании) — это тип данных, операции над значениями которого напрямую или достаточно эффективно поддерживаются командами компьютеров. Такие типы обычно входят в состав встроенных типов данных и используются в системном программировании или низкоуровневых языках программирования. В языках более высокого уровня большинство типов данных абстрагированы — они не имеют определённого машинного представления.

### Производительность оперативной памяти
Производительность оперативной памяти - скорость доступа к процессора к данным, размещённым в ОЗУ
1. **Время доступа** - это время, которое мы ожидаем после запроса за данные до времени их получения
2. **Время цикла** - это время, которое мы ождаем от момента обращения к памяти до возможности подачи следующего запроса

- При чтениее данные портяться, для этого мы дополнительно делаем запись.
- По статистике команд для чтения больше, чем для записи.

## Центральный процессор
**Центральный процессор** - главная вычислительная мощность. Есть ещё перефирийные процессоры, которые занимаются, к примеру, контролем подключения внешней памяти

**Устройство управления** - координация выполнения команд
**Арифметико-логическое устройства** - выполнение команд, арифметической или логической обработки операндов
**Регистровая память** - совокупнсоть устройств памяти процессора - регистров

**Кэш-память** - буферизации работы процессора с оперативной памятью
	- Существует для снижения количества обращение к памяти

### Рабочий цикл процессора
![[Pasted image 20250918091324.png]]
Пусть в счётчике команд есть некоторая память. Выбираем команду и рзамещаём внутри процессора в специальный регистр. Мы автоматически увеличиваем счётчик команд на единичку. Анализируем код операции. Возможны 3 варианта анализа: 1. логическая или арифмитическая операция; 2. команда передаёт управление; 3. процессор не может исполнить операцию, если команд с таким кодом в процессоре нет, или процессор рабоает в режиме, в котором запрещено исполнение некоторых команд (тогда фиксируем ошибку). 

### Кэш-памяти
- Обсуждаем кеш внутри процессора. Кэш первого уровня

- Кэш-память работает той же скоростью, что и процессор.
- Кэш - буффер памяти, разделёнынй на блоки фиксированного размера. Размер кэш памяти - степень двойки.
- У каждой ячейки есть поле тега - размещается служебная информация, которая используется для организации работы кэша.
- В те моменты, когда процессор вычисляет исполнительный адрес и по этому адресу обращается в оперативку, на самом деле происходит следующее:
	- сначала в процессоре автоматически происходит блока в кэша, котороый содержит адрес, по которому хотим обратиться в медленную память. Поиск происходит параллельно и по тегам.
	- 1. Мы нашли блок кэша - фиксируем попадания. Мы не обращаемся совсем к оперативке
	- 2. Если в кэше такого адреса нет, то в этом случае фискируется промах. Мы должны решить 3 задачи:
		1. Найти блок кэша, который мы "выгрузим" (на его место попытаемся разместить блок из оперативной памяти, в которой находится искомый адрес). Выбор этого блока может происходит по разным сценарием: к примеру случайно.
		2. Что делать с содержимым этого блока: есть разные стратегии, к примеру **сквозное кэширование** - то в случае, если встречаемся команда записи, при попадании коректируется соответствующая строка блока, и блок сбрасывается в оперативку. Вторая модель - **кэширование с обратной связью** - в этом случае в теге каждого блока может находиться признак того, что содержимое блока изменено. Если появляется команда записи, то обновляем инфомацию в кэше, в которую попали, и в тег устанавливаю признак, что данные изменились. Если этот блок попадает под вытеснения, аппартура процессора автоматически смотрит на кеш блока, если там указано, чтло блок изменялся, то содержимое сбрасывается в оперативку. Если не изменяли, то просто забываем.
		3. Загрузка нужного блока в кэш. 2 момента:
			1. Используется то, что размер блока 2 в степени. От начала оперативки проходимся по блокам.
			2. Загрузка, работа кэша с оперативкой происходит блочно и параллельно: параллельно чтение оперативки из кэша и запись из кэша в оперативку.

1. Обмен данными между кэшем и оперативной памятью осуществляется **блоками** фиксированного размера
2. **Адресный тег** блока — содержит служебную информацию о блоке (соответствие области ОЗУ, свободен/занят блок, …)
3. Нахождение данных в кэше – **попадание** (**hit**). Если искомых данных нет в кэше, то фиксируется **промах (cache miss)**
4. При возникновении промаха происходит обновление содержимого кэша **—** **вытеснение**. Стратегии вытеснения:
	- случайный выбор блока 
	- вытеснение наименее «популярного» блока (LRU — Least-Recently Used)
5. Вытеснение кэша  данных:
	- **сквозное кэширование** (write-through caching) 
	- **кэширование с обратной связью** (write-back cache) — тег   модификации (dirty bit )

- Благодаря локализации минимизируется количество промахов. 
- 2 типа обращения к памяти: за командами и операндами

# Аппарат прерываний
- **Прерывания** - событие в компьтере, при появлении которого аппартура компьютера реагирует некоторым стандартным образом. При этом событие это событие из ограниченого списка событий, который определялся при разработке процессора.

## Типы прерываний
1. **Внутренние** - прерывания, которые возникают, по инициативе схем контроля компьютера (процессора).
	- Примеры: попытка исполнения запрещённой команды или обращение к запрещённой или не существующей области памяти. Или при обращении к RAM сработал контроль счётности.
2. **Внешние** - инициируется в результате взаимодействия процессора с внешним миром (внешними устройствами). Это почти всегда не ошибка
	- Обращение к жётскому диску за считывания блока, и контроллер диска даёт нформацию, что считывание произошло успешно.

## Простейшая учебная схема обработки прерываний
![[Pasted image 20250918100101.png]]
- Атомарность машинный команд
- Актуальное состояние процессора включает в себя совокупность определённых регистров, которые нужны для продолжение выполнения программы с точки остановы. Происходит автоматически
- Сохрание части регистров общего назначения, чтобы мы могли запустить программу обработки прерываний. Происходит автоматически

# Виртуальная память
**Вирутальная память** - память, которая используется внутри нашей программы (виртуальное адресное пространство).

**Второе адресное пространство** - физическая оперативная память, в неё загружается исполняемый код.

Аппаратно-программное средство вычислительной системы производит перенос виртульных адресов в физические адреса.

![[Pasted image 20250925090042.png]]
## Аппарат базирования
- Первая модель это **базирование адресов** - в программе исполнительный адрес может быть 2-х типов:
	1. Абсолютный исполнительный адрес
		- Полностью соответсвутет адресу в физ памяти
	2. Относительный (адрес относительно начала программы)
		- Отображение области 1 в 1, обязательно непрерывную
		- Представляются в виде адреса исполнительной программы + содержимое некоторого регистра (спец или общий), который называется **регистор базы**. В регистор базы ос загружет адрес начала загрузки.
		- Организация виртуального адреса пространства
		- Можно разделить пространства для кода и для данных. Аппаратура может поддерживать свои базовые регисторы.

**Аппарат виртуальной памяти** — аппаратные средства компьютера, обеспечивающие преобразование (установление соответствия) программных адресов, используемых в программе с адресами физической памяти, в которой размещена (или будет размещена) программа во время выполнения.

## Страничная организация

- Виртуальная и физическая память разделяется на блоки фиксированного размера - некоторая степень двойки
- Совокупность двух полей: 
	1. поле длиной k байтов (младшие разряды) - смещение адреса относительно начала страницы
	2. старшие разряды - номер страницы

Аппратное-программное средство, которое позволяет производить отображение виртуального страничного адреса в страничный физический адрес. Так как и физическая и виртутальная память разделены на эти самые странички.

Номер виртуальной страницы размещён в каком-то номере физической страницы. В системе есть табличка сопоставления.

		- Содержимое страниц можно временно сбрасывать на жесткий диск в файл подкачки, а при необходимости – загружать обратно в физическую память

## Компьютерная сеть
- **Компьютерная сеть** - объединение компьютеров (вычислительных систем), взаимодействующих через коммуникационную среду.
- **Коммуникационная среда** — каналы и средства передачи данных.

### Составляющие компьютерной сети
- Абонентские или основные компьютеры — **хосты** 
- Коммуникационные или вспомогательные компьютеры  (**шлюзы**, **маршрутизаторы**, …)

### Модели организации сетей
- Сеть коммутации каналов
- Сеть коммутации сообщений
- Сеть коммутации пакетов

**Сообщение** - порция данных, произвольного размера (в обще случае).

- Взаимодействие абонентов осуществляется сеансами связи. **Сеанс связи** состоит из обмена сообщениями между абонентами. Начало/завершение сеанса связи.

#### Сеть коммутации каналов
Обеспечивает выделение коммутации абонентам коммуникации на весь сеанс связи.

**Преимущества**:
- После установки соединения, сеть находится в состоянии готовности
- Организация такой сети не требует сложного поддерживающего обородувания
- Не требуются наклодные расходы
- Детерминированная пропускная способность

**Недостатки**:
- Выделяется на сеанс связи - избыточность сети
- Период ожидания выделения канала
- Неэффективное использование выделенного канала
- Повтор в случае сбоев

#### Сеть коммутации сообщений
Взаимодействие в виде последовательности обменов сообщениями.

**Преимущества**:
- Отсутствие занятости канала на недетерминированный промежуток времени
- В этой сети не происходит долговременной блокироваки соединения

**Недостатки**:
- Необходимость буфферизации из-за того, что сообщение может быть любого размера
- Необходимость в специализированном коммуникационном оборудовании и ПО
- Повтор передачи всего сообщения в случае сбоя

#### Сеть коммутации пакетов
- Каждое сообщение разбивается на блоки фиксированного размера - **пакеты**. Структура пакета (заголовок, данные)

**Преимущества**:
- Так как известна топология сети и характеристики её элементов, то возможно определение требований в коммутационных узлах возможна оценка размера буфера и времени доставки пакетов

**Недостатки**:
- Увеличение трафика из-за наличия заголовочной информации
- Проблема сборки пакетов

### Пакетная коммуникация
Пакет логические состоит "содержательной" информации (что нужно передать) и служебной информации (адрес отправителя и получателя, контрольные суммы (проверка на битый пакет), дата, время)

Если пакет не дошёл, то отправляем его снова

**Минусы**:
- Накладные рассходы - передача служебной информации
- Сборка пакетов
- Нагрузка на сеть за счёт перемещения не только содержательных пакетов, но и пакетов уведомлений. Существенная нагрузка на коммуникационную среду (10% полезного, 90% накладных рассходов)
 

- Леонард Клейнрок (MIT) 1961 г. Публикация по пакетной коммутации. 
- DARPA - Defence Advanced Research Projects Agency, 1967 г. проект ARPANET (1969 г. первая конфигурация)
	- Заказала устойчивую компьютерную сеть, которая получила название ARPANET
	- Сначала проект был военный, потом передался в университеты

## Модель OSI/ISO организации взаимодействия сети
**Уровени**:
1. Физический уровень
	- Стандартизация конкретной физической среды передачи данных
	- На этом уровне обеспечивается передача потока двоичной информации
	- Декларируются сигналы и аппаратные интерфейсы соединения
2. Канальный уровень
	- Стандартизуются правила доступа, вопросы синхронизации, выявление и попытка исправления ошибок, возникающих при передаче данных
	- Цель - надёжная передача данных
3. Сетевой уровень
	- Решаются проблемы взаимодействия сетей
	- Уровень декларирует интернет взаимодействие
	- Работает в рамках конкретных локальных сетей
4. Транспортный уровень
	- Организация передачи данных между программой отправителя и программой получателя
	- На это уровне передача может решаться в 2-х моделях: 1. Передача с установленим виртуального канала (он гарантирует доставку пакета, занимается сбором и организации сообщения в виде пакетов); 2. Транспорт , который не предполагает установления виртуального канала (отправляет пакет в сеть и забывает о нём). 
5. Сеансовый уровень
	- На этом уровне определяются активности сторон, полномочия сторон
6. Представительский уровень
	- Уровень представления
	- Много кодировок
	- Решение задачи унификации представления
	- Создание одного единого представления (в идеале), но в реальности такое невозможно
7. Прикладной уровень
	- Формализация организации и взаимодействия прикладный систем
	- Пример: почтовые клиенты

Осталась как академическая модель организации сетевого взаимодействия, но она повлияла очень сильно. Сформировала набор определений и понятий, которые используются в сетевом вазимодействии, но и в частности такие термины как:
- **Протокол** (**правила взаимодействия одноименных уровней**) — формальное описание сообщений и правил, по которым сетевые устройства (вычислительные системы) осуществляют обмен информацией. Правила взаимодействия одноимённых (одноранговых) уровней сети. 
- **Интерфейс** - правила взаимодействия вышестоящего уровня с нижестоящим
- **Служба (сервис)** - набор операций, предоставляемых нижестоящим уровнем вышестоящему
- **Стек протоколов** - перечень разноуровневых протоколов, реализованных в системе

## Семейство протоколов TCI/IP
80-е годы. Изначало появились в развитии проекта ARPANET. **Это не протокол, а семейство протоколов**. Два мейнстрим протокола: IP и TCI. 
**Уровни:**
1. Уровень доступа к сети
2. Межсетевой уровень <- здесь живёт протокол IP
3. Транспортный уровень <- здесь живёт протокол TCI
4. Уровень прикладных программ
### Соответствие модели ISO/OSI модели семейства протоколов TCP/IP
1. **Уровень доступа к сети** == Канальный + физический уровень
	- Специфицирует доступ к физ сети
2. **Межсетевой уровень** == Сетевой уровень
	- В отличие от сетевого уровня модели OSI, не устанавливает соединений с другими машинами
3. **Транспортный уровень** == Сеансовый уровень + транспортный уровень
	- Обеспечивает доставку данных от компьютера к компьютеру, обес-печивает средства для поддержки ло-гических соединений между прик-ладными программами. В отличие от транспортного уровня модели OSI, в функции транспортного уровня TCP/IP не всегда входят контроль за ошибками и их коррекция. TCP/IP предоставляет два разных сервиса передачи данных на этом уровне. Протокол TCP,  UDP (не устанавалиет виртуальны канал).
4. **Уровень прикладный программ** == Уровень прикладных программ+ Уровень представления данных
	- Состоит из прикладных программ и процессов, использующих сеть и доступных пользователю. В отличие от модели OSI, прикладные про-граммы сами стандартизуют пред-ставление данных.

### Свойства протоколов семейства TCP/IP
- Открытые
- Независимость от аппаратного обеспечения сети передачи данных
- Общая схема именования сетевых устройств
- Стандартизованные протоколы прикладных программ

### Уровень доступа к сети
На уровне доступа к сети протоколы обеспечивают систему средствами для передачи данных  другим устройствам в сети

- Проблема общей шины: пропускная способность самой шины, количество сетевых устройств, интенсивность работы сетевых устройств с шиной. Шина и сеть начинают деградировать
#### Пример
**Протокол Ethernet** - разработка исследовательской компании Xerox (1976 год). Единая шина - широковещательная сеть. Для сетевых устройств обеспечивается множественный доступ, с контролем и обнаружений конфликтов (Carrier Sense Multiple Access with Collision Detection - CSMA/CD)
- У всех уникальные Ethernet (MAC) адреса

### Межсетевой уровень 
- Функции протокола IP
	- формирование дейтаграмм
	- поддержание системы адресации
	- обмен данными между транспортным уровнем и уровнем доступа к сети
	- организация маршрутизации дейтаграмм
	- разбиение и обратная сборка дейтаграмм
- IP — протокол БЕЗ логического установления соединения 
- Протокол IP НЕ обеспечивает обнаружение и исправление ошибок

- Самое главное - IP адресация

### Транспортный уровень
- На нём есть 2 ключевых протокодла: TCP, UDP.
- TCP - безопасное соединение с исправлением ошибок

- **Протокол контроля передачи** (**TCP**, Transmission Control Protocol) обеспечивает надежную доставку данных с обнаружением и исправлением ошибок и с установлением логического соединения. 
- **Протокол пользовательских дейтаграмм** (**UDP**, User Datagram Protocol) отправляет пакеты с данными, не контролируя их доставку.
- TCP обеспечивает последовательную передачу пакетов, контроль доставки пакетов, отработку сбоев.

### Уровень прикладных программ
На основе TCP базируются прикладные протоколы, которые обеспечивают либо доступ и работу с заведомо корректной информацией, которая осуществляется в сети Интернет.

- Протоколы, опирающиеся на TCP 
	- TELNET (Network Terminal Protocol) 
	- FTP (File Transfer Protocol) 
	- SMTP (Simple Mail Transfer Protocol) 

- Протоколы, опирающиеся на UDP 
	- DNS (Domain Name Service) 
	- RIP (Routing Information Protocol) 
	- NFS (Network File System)
